# BetterOff CLI

Read your [BetterOff](https://betteroff.finance) household from the terminal: accounts, net worth, transactions, spending, cash flow, recurring bills, portfolio, and debts.

The CLI is read-only. It cannot move money, change records, or approve anything.

```console
$ betteroff accounts
Display name                  Balance     Available balance  Balance as of     Type
Everyday Checking (...1234)   $4,210.55   $4,190.55          2026-10-22 16:00  depository
High-Yield Savings (...8841)  $18,250.00  $18,250.00         2026-10-22 16:00  depository
Rewards Visa (...0912)        $612.40     $9,387.60          2026-10-22 16:00  credit
Brokerage (...5530)           $52,318.09  $1,204.11          2026-10-22 16:00  investment
Solana Wallet (...7xQp)       $88.12      -                  2026-10-22 16:00  crypto
2 more columns hidden; use --json for everything

As of 2026-10-22 16:00 UTC
```

The accounts above are made up.

## Install

There are no release binaries yet. Run it from source with [Bun](https://bun.sh) 1.4.3 or later:

```sh
git clone https://github.com/raintree-technology/betteroff.cli.git
cd betteroff.cli
bun install --frozen-lockfile
bun src/main.ts --help
```

To build a single binary at `dist/betteroff`:

```sh
bun run build
```

## Sign in

1. In BetterOff, open [Settings > API tokens](https://app.betteroff.finance/settings/api-tokens) and create a token with read scopes only.
2. Run `betteroff login` and paste the token. The CLI checks it with BetterOff and saves it in your system keychain: macOS Keychain (through Apple's `security` tool, so upgrades never prompt for access), libsecret on Linux, or Windows Credential Manager.

`betteroff status` shows which token and API the CLI uses. `betteroff logout` removes the saved token.

On a machine where the keychain is locked or unavailable, such as an SSH session or CI, set `BETTEROFF_API_TOKEN` instead.

## Use

```sh
betteroff overview
betteroff accounts
betteroff transactions --merchant "whole foods" --all-time
betteroff transactions --start-date 2026-09-01 --end-date 2026-09-30 --traits travel
betteroff analyze-spending
betteroff recurring
betteroff portfolio --group-by account
betteroff net-worth-history
betteroff debts
```

Run `betteroff --help` for every command and `betteroff <command> --help` for its flags.

In a terminal, results print as tables and labeled fields, with paging, data quality, and freshness notes at the end. When output is piped, or with `--json`, the CLI prints the exact JSON result, so it works in scripts and as a tool for AI agents:

```sh
betteroff recurring --json | jq '.data'
```

Lists are paged. When there is more, the footer prints the `--cursor` value for the next page.

## How it works

The CLI calls BetterOff's public tool API, `POST https://api.betteroff.finance/v1/tools/<tool>`, the same tools the BetterOff MCP server offers. Its commands and flags come from the public spec at [`/openapi/tools.json`](https://api.betteroff.finance/openapi/tools.json), cached for an hour in `~/.cache/betteroff`. A new read tool in BetterOff shows up as a command without a CLI update.

Only tools the spec marks read-only become commands. Tools that propose changes or request transfers are left out, even if the spec labels one read-only by mistake. The token's scopes are the real limit, so give it read scopes only.

## Environment variables

| Variable | Use |
| --- | --- |
| `BETTEROFF_API_TOKEN` | Personal API token (`bo_pat_...`). Overrides the saved token. |
| `BETTEROFF_API_URL` | API origin. Defaults to `https://api.betteroff.finance`. |
| `NO_COLOR` | Any value turns off terminal styling. |

## Security

- **Read-only.** Only tools the spec marks read-only become commands, and tools that propose changes or request transfers are left out by name as well. Give the token read scopes only; the token's scopes are the limit BetterOff enforces.
- **The token goes only to the BetterOff API, over HTTPS.** It is saved in the system keychain, never in a file. On macOS it goes through Apple's `security` tool on stdin, never on a command line. `BETTEROFF_API_URL` must be an `https://` origin (`http://` only for localhost), and the CLI never follows a redirect, so the token cannot be sent somewhere else by mistake.
- **Pinned trust.** Requests trust a bundled Mozilla root certificate snapshot (`src/ca.pem`) instead of Bun's built-in list, which still includes roots Mozilla has distrusted.
- **Safe terminal output.** Merchant names and other text come from banks and other third parties. The CLI replaces control characters and bidirectional overrides before printing, so that text cannot move the cursor, rewrite the screen, set the clipboard, or reorder what you see. `--json` output escapes the same characters and still parses to the same value.
- **Supply chain.** Dependencies are pinned to exact versions with a frozen lockfile, and new releases wait 3 days before install. CI actions are pinned to commit SHAs with read-only tokens. CodeQL scans the code and workflows. OSV-Scanner checks every version in `bun.lock` against known vulnerabilities on each pull request and daily. Pull requests also fail on vulnerable new Actions, and Socket reviews dependency changes.

Report a vulnerability to [security@betteroff.finance](mailto:security@betteroff.finance), not in a public issue. See [SECURITY.md](SECURITY.md).
